# 代码阅读指南

给第一次读这份代码的人（也包括几个月后忘了细节的自己）。

这份指南回答三件事：**哪些代码要读、按什么顺序读、会遇到哪些语法。**

---

## 一、先搞清"哪些代码是谁的"

仓库里一共 **7 个 `.mbt` 文件**（拆成"库 + 命令行"两个包之后）：

| 文件 | 行数 | 是谁的 |
|---|---|---|
| `cif.mbt` | 919 | ✅ **自己写的** —— 库主体（数据模型、几何、对称操作、对外 API） |
| `spacegroup_table.mbt` | 241 | ✅ 自己的（但**内容是脚本生成的**，别手改） |
| `cmd/main/main.mbt` | 98 | ✅ **自己写的** —— 命令行入口（读参数、读文件、打印） |
| `cmd/main/format.mbt` | 88 | ✅ **自己写的** —— 排版（fmt / print_report…） |
| `cif_wbtest.mbt` | 388 | ✅ **自己写的** —— 白盒单元测试（35 条） |
| `vendor/crystal/crystal.mbt` | 1078 | 📦 借来的（Apache-2.0） |
| `vendor/crystal/utils.mbt` | 348 | 📦 借来的 |

**判断规则**：

> **在 `vendor/` 文件夹里的 = 借的；不在的 = 自己的。**

语言自带的库（`moonbitlang/core`、`moonbitlang/x`）**不算"借"** ——
它们像水电一样是语言的一部分，不用标注来源。

借了什么、从哪借的、改过没有，都写在 [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md)。

## 二、跟借来的代码只碰 6 个地方

在 VS Code 里搜 `@bio.`（这是我们给借来的代码起的简称）能找到全部接触点。
**这些接触点全在 `cif.mbt` 一个文件里**（大致就两处：`block_scalar` / `block_number`
附近，以及对外入口 `parse_cif`）：

| 调用 | 它给什么 | 要注意什么 |
|---|---|---|
| `block.get_scalar(key)` | 一个值（字符串） | 找不到时给**空字符串 `""`**，不是 `None`、不报错 —— 所以才有 `block_scalar` 这层翻译 |
| `block.get_loop(key)` | 一张表（表头 + 数据行） | 找不到时给空的；**行字段数 ≠ 表头数时那一行会被丢弃**（后面会整体错位） |
| `block.get_loop(key)` | 同上 | 同上（这里只用表头） |
| `block.get_loop(key)` | 同上 | 同上 |
| `@bio.parse_cif(text)` | 几个数据块 | 文件**没有 `data_` 行**时返回空 |
| `@bio.parse_cif(...)` | 同上 | 补救：补一行 `data_unnamed` 再试一次（在 `parse_cif` 里） |

> 指南里**不再写具体行号**了 —— 拆库那次改动让行号全变了，写死行号只会误导人。
> 用 `Ctrl+Shift+O`（大纲）或直接搜函数名定位，永远准。

**要验证的就是这 6 处，不是那 1426 行。** 理由（重要）：

> **你的验证结果依赖借来的输入。** 借来的那层如果读错了坐标，
> 你的代码再正确，输出还是错的 —— 而且因为你的逻辑没问题，错误会更隐蔽。
>
> 这不是假设：`mp-crlf.cif` 就踩过一次（表头 13 列、数据行写了 14 个值）。

**两个好消息**：

1. 借来的代码**只给我们"文字"，一个数字都不解释** —— 所以"单位是度还是弧度""是分数坐标还是笛卡尔坐标"
   这类经典陷阱，在这条边界上**不存在**（数字全是我们自己转的）
2. 它给的是**复印件**（内部做了 `.copy()`）—— 我们怎么读都不会弄坏它的内部状态

## 三、MoonBit 和 Python 最不一样的 5 个地方

| MoonBit 写法 | Python 里对应 | 坑在哪 |
|---|---|---|
| `let x = 1` **不可变**；要改必须 `let mut x = 1` | Python 变量都能改 | 忘了 `mut` 直接编译报错 |
| 结构体字面量**必须标类型**：`let lat : Lattice = { a: 1.0, ... }` | dict/class 不用 | 不标类型编译器推断不出（`cif.mbt` 里到处是 `: SymComponent` 就是这个原因） |
| `expr catch { _ => 默认值 }` —— **catch 是表达式**，能直接赋值 | `try/except` 是语句 | 它最特别的地方，见 `parse_number`（搜函数名就能找到） |
| `'a'` 是 **Char**，`"a"` 是 **String**，两种不同类型 | 单双引号没区别 | 所以要写 `c.to_string()` |
| 函数**必须写返回类型**：`-> Double` | 不用 | 不写会报 error 4074 |

**其余基本能对上**：`[]` 是数组（像 list）、`@math.cos(x)` 像 `math.cos(x)`、
`raise Failure("x")` 像 `raise ValueError("x")`、`let (x,y,z) = f()` 像元组解包、
`变量.函数(参数)` 和 Python 一模一样。

### 顺便说清 `Some` / `None`

```moonbit
fn block_scalar(block : @bio.CifBlock, key : String) -> String? {
  let value = block.get_scalar(key)
  if value == "" {
    None          // 没有
  } else {
    Some(value)   // 有，就是这个值
  }
}
```

- `String?` 里的 `?` 读作"**可能没有**"（`String` 是"一定有"，`String?` 是"可能有"）
- `Some(值)` = "有"；`None` = "没有" —— 就这两个选项
- 像**信封**：`Some("3.84")` 是装着纸条的信封，`None` 是没有信封。**必须拆开才能拿到里面的东西**
- **为什么非要包一层**：因为空字符串有歧义（"没有这一项" 和 "这一项就是空的" 分不开）
- **最大的好处**：调用方**不能装作"一定有值"** —— 类型是 `String?`，不处理 `None` 就编译不过

## 四、分 6 段读（每段一个语言主题，共约 5 小时）

**不要从第 1 行读到最后一行** —— 那 700 行管道代码（找列、取表、打印、主流程）
现在读了记不住，也没必要。

| 段 | 行号 | 学到的语言点 | 读完做这个实验 |
|---|---|---|---|
| **0**<br>20 分钟 | **20–90**<br>数据结构 | `struct` / `enum` 语法、字段、类型标注、常量 | 把 `comp_tol`(89 行) 从 `0.01` 改成 `0.9`，跑 `check_fail_ratio.cif`，看警告是否消失 |
| **1**<br>40 分钟 | **95–124**<br>几何 | 函数签名与返回类型、算术表达式、`if/else` **当表达式用**、方法调用 `.sqrt()`、包别名 `@math.` | 把 `to_radian` 里的 `/ 180.0` 改成 `/ 100.0`，看体积变成多少（体会"忘了换算"的后果） |
| **2**<br>60 分钟 | **518–538**<br>`parse_fraction` | `match` + `Option`（`Some`/`None`）、`raise`、`catch`、字符串方法 `split_once` | 把分母判断 `denominator == 0.0` 删掉，用含 `1/0` 的 CIF 试 |
| **3**<br>60 分钟 | **540–562** + **564–598**<br>`parse_term` / `parse_component` | `let mut`、`while` / `for`、字符比较、累加器模式、数组字面量 `[cx, cy, cz]` | 把 `parse_term` 里 `number == ""` 时默认的 `1.0` 改成 `0.0`，看 `-x+y+1/2` 会解析成什么 |
| **4**<br>60 分钟 | **687–706** + **708–723**<br>`apply_symop` / `wrap01` | **元组返回**与解构、嵌套 `for`/`while`、数组索引 `src[i]` | 把 `wrap01` 的两个 `while` 注释掉，跑 `sym_demo.cif`，看坐标怎么变成负数 |
| **5**<br>60 分钟 | **725–752** + **754–778**<br>`frac_same` / `has_same_site` / `expand_atoms` | 布尔表达式组合 `&&`、逻辑非 `!`、结构体字面量构造与 `push`、三层嵌套 | 把 `has_same_site` 的判断去掉，跑 `frac_demo.cif`，看原子数变多 |

**每段的读法**：先只看**函数签名 + 注释**，猜实现怎么写的 → 再读实现对照 → 最后做那个实验。

## 五、三个提速技巧

| 技巧 | 怎么做 |
|---|---|
| **跳转而不是数行号** | 按住 `Ctrl` 点函数名 → 直接跳到定义（或按 `F12`） |
| **先看骨架** | `Ctrl+Shift+O` 打开当前文件的大纲，一眼看到所有函数名 |
| **`Ctrl+G` 跳行号** | 想直接去某一行就用这个（比搜索快） |

**放心改**：代码已经提交、已推送，改坏了随时还原：

```powershell
git diff                    # 看我改了什么
git checkout -- cif.mbt    # 一键全部还原
```

**这是学语言最关键的心理前提** —— 有了安全网，你才敢主动把代码弄坏看会怎样。
