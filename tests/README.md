# 测试用例

> ⚠️ **重要**：这些文件曾经放在系统临时目录 `%TEMP%` 里，结果被 Windows 定期清理**全部丢失**。
> 所以它们现在是仓库的一部分 —— **测试数据必须进版本控制，不能放在临时目录。**

## 怎么跑

### 一键验证（推荐用这个）

```powershell
python tests/tools/verify.py
```

一条命令跑完 **27 项检查**，逐条打印 `[OK]` / `[FAIL]`，最后给总结。
例如：

```
第 1 组：真实 Materials Project 数据（期望值 = 文件自带的 _cell_volume）
  [OK]   mp-149.cif               V=40.329527      官方=40.32952685    警告=0
  [OK]   GaN-P6_3mc.cif           V=45.728324      官方=45.72832359    警告=0
第 2 组：对称展开（期望值 = pymatgen 独立计算）
  [OK]   frac_demo.cif    原子数=3  坐标逐条一致（与 pymatgen）
...
结果：27 项检查，通过 27，失败 0
```

**四组检查，期望值分别来自**：

| 组 | 内容 | 期望值来源 |
|---|---|---|
| 1 | 8 个真实 MP 文件 | **文件自带的 `_cell_volume`**（Materials Project 官方发布值） |
| 2 | 3 个对称展开用例 | **pymatgen**（第三方独立实现） |
| 3 | 4 个合成用例 | **从文件里的 `a` 自算**（立方 V = a³） |
| 4 | 12 个错误用例 | ⚠️ 手写关键词 —— 只有这一组没办法 |

> **为什么期望值要这么设计**：如果期望值由写代码的人自己写，他写错了测试也会通过 —— 
> 那不叫验证，叫自证。所以前三组的期望值全部来自**独立来源**；
> 只有第 4 组的"提示关键词"是手写的（因为那是在测我们自己的报错文案，没有第三方可对照）。

### 单独跑一个用例

```powershell
# 第二参数是出错策略，默认 warn
moon run . -- tests/functional/sym_demo.cif
moon run . -- tests/functional/frac_demo.cif raise
```

## `functional/` —— 功能用例（9 个，都应当正常出结果）

| 文件 | 测试点 | 期望结果 |
|---|---|---|
| `sym_demo.cif` | 2 条对称操作 + **负坐标折回**：`-x` 作用在 0.25 上得到 −0.25，必须折回成 0.75 | 1 块；V=63.027696；**2** 个原子；对称操作 2 条；组成 `Na2`；0 警告 |
| `symmetry.cif` | 同上，但换成 `_space_group_symop_operation_xyz` 这个**别名关键字** | 与 `sym_demo.cif` 完全一致 |
| `frac_demo.cif` | **1/3、2/3 分数平移**：原子在原点，三个方向的三重轴应展开出 0、1/3、2/3 | 1 块；V=108.253175；**3** 个原子；对称操作 3 条；组成 `M3`；0 警告 |
| `two_blocks.cif` | **一个文件两个数据块**，不能混在一起 | 2 块；V=125 与 V=729；各 2 个原子；组成 `A2` / `B2`；0 警告 |
| `nodata.cif` | 故意漏写 `data_` 行（手写 CIF 常见）→ 应当宽容处理 | 1 块；V=64；1 个原子；组成 `Q1`；**1 警告**（文件里没有 data_ 行） |
| `check_pass.cif` | 化学式自检**应当通过**：解析出 Ga₄O₆，CIF 写 `Ga2 O3`，比值 4/2 = 6/3 = 2 | 1 块；V=125；10 个原子；组成 `Ga4 O6`；**0 警告** |
| `check_fail_ratio.cif` | 化学式自检**应当报警**：解析出 Ga₄O₄，比值 4/2 = 2 而 4/3 = 1.33，差 0.67 | 1 块；V=125；8 个原子；组成 `Ga4 O4`；**1 警告**（配比不一致） |
| `check_fail_missing.cif` | 化学式自检**应当报警**：CIF 声称含 H，解析结果里一个 H 都没有 | 1 块；V=125；6 个原子；组成 `C2 N2 O2`；**1 警告**（缺元素） |
| `mp-crlf.cif` | **CRLF 换行** + 真实 MP 导出的 **13 列**原子表（label 不是第一列） | 1 块；V=160.191478（= 5.431³）；**8** 个原子；组成 `Si8`；0 警告 |
| `symop-gan-p63mc.cif` | **真实的多条对称操作**：P6₃mc，12 条（含 `z+1/2` 平移和 6₃ 螺旋轴） | 1 块；V=45.728323；不对称单元 2 个 → 展开 **4** 个原子；组成 `Ga2 N2`；0 警告 |
| `symop-ga2o3-c2m.cif` | 单斜 C2/m，8 条（C 面心 + 螺旋轴） | V=211.467526；不对称单元 5 个 → 展开 **20** 个原子；组成 `Ga8 O12`；0 警告 |
| `symop-sic-f43m.cif` | 立方 F-43m，96 条 | V=82.53977；不对称单元 2 个 → 展开 **8** 个原子；组成 `Si4 C4`；0 警告 |
| `symop-diamond-fd3m.cif` | 金刚石型 Fd-3m，**192 条**（最极端） | V=45.146352；不对称单元 1 个 → 展开 **8** 个原子；组成 `C8`；0 警告 |

> **`symop-*` 这四个文件是怎么来的**：Materials Project 导出的 CIF 全部是 `P 1`（只有 1 条
> `'x, y, z'`），也就是说在补上这四个文件之前，**"多条对称操作"从来没被真实验证过**。
> 它们是用 `tests/tools/make_symmetry_cases.py` 生成的：拿真实的 MP 结构，用 spglib 把对称性找回来，
> 再写出带完整显式对称操作的 CIF。**产物 = 真实材料 + 真实对称操作。**
>
> **金刚石那条是真正的考验**：192 条操作作用在 1 个原子上，正确结果是 **8 个不同位置**
> （其余 184 个全是重复）。我们的周期性去重逻辑必须把它压成 8，多一个少一个都是错的。

> 📌 `mp-crlf.cif` 特意保持 **CRLF** 换行（见根目录 `.gitattributes` 里的例外声明），
> 否则这个用例就失去意义了。

## `errors/` —— 错误用例（12 个，都应当**优雅报错且不崩溃**）

| 文件 | 故意做错了什么 | 期望的提示 |
|---|---|---|
| `01-empty.cif` | 文件是**空的**（0 字节） | `错误：文件是空的，或者没有权限读取` |
| `02-only-comments.cif` | 整个文件**只有注释** | `文件里没有 data_ 行，按单个匿名数据块处理` + 最后报"没有解析出任何结构" |
| `03-missing-param.cif` | 少了 `_cell_length_c` | `文件里找不到晶格参数 _cell_length_c` |
| `04-not-a-number.cif` | `_cell_length_a` 写成 `abc` | `"abc" 不是合法数字` |
| `05-question-mark.cif` | 用 CIF 的 `?`（表示"不知道"） | `数值缺失（文件里写的是 "?"）` |
| `06-dot.cif` | 用 CIF 的 `.`（表示"不适用"） | `数值缺失（文件里写的是 "."）` |
| `07-illegal-angle.cif` | 三个夹角都是 170° —— **物理上凑不出晶胞** | `晶格角度凑不出真实晶胞（α=170° β=170° γ=170°），体积只能算作 0` |
| `08-bad-coord.cif` | 坐标写成 `xyz` | `坐标位置读到的值是 "xyz"，不是合法数字（最常见的原因：这一行字段数和表头对不上…）` |
| `09-missing-column.cif` | 原子表**缺 `_atom_site_fract_z` 列** | `原子位点表缺列：必须有 _atom_site_fract_x / _y / _z` |
| `10-short-row.cif` | 数据行字段数（2）少于表头数（4） | `原子位点表只有表头，没有一行完整的数据（每行列数要和表头对得上）` |
| `11-upper-key.cif` | 关键字写成全大写 `_CELL_LENGTH_A` | `文件里找不到晶格参数 _cell_length_a`（已知局限：不做大小写折叠） |
| `12-bracket.cif` | 误差括号写坏：`5.43(2` 和 `5.43()` | 不报错，`a`/`b` 都读成 5.43；因无原子表而提示"没有找到原子位点表" |

## ⚠️ 造测试文件时最容易犯的错

**CIF 的表格是纯空白分隔、不带列名的**。所以：

> **每一行的字段数，必须和表头数完全一致。多一个、少一个都会出错。**

这不是理论提醒 —— 这个坑先后踩过**两次**：

1. 第一次：`mp-crlf.cif` 表头 13 列，数据行写了 **14** 个值 → 借来的分词器丢掉那一行，
   **后面所有行整体错位**（第 2 行的坐标串到了第 3 行）
2. 第二次：重建这个文件时，**又**在行尾写了 4 个点（应该 3 个）→ 同样的问题

**建完文件请务必数字段数**：

```powershell
$p = "tests/functional/mp-crlf.cif"
Get-Content $p | Where-Object { $_.StartsWith("_atom_site") } | Measure-Object   # 表头数
Get-Content $p | Where-Object { $_.StartsWith("Si") } | ForEach-Object { ($_ -split '\s+').Count }  # 每行字段数
```

## `tools/` —— 脚本

| 脚本 | 作用 |
|---|---|
| `verify.py` | **一键验证**（上面那个）。跑完全部检查并给出总结 |
| `verify_with_pymatgen.py` | 只做对称展开的对照，把 pymatgen 的展开结果打印出来给人看 |
| `make_symmetry_cases.py` | **生成 `symop-*` 高对称用例**：用 spglib 把真实结构的对称性找回来，写出带完整对称操作的 CIF |

前两个需要 pymatgen：`pip install pymatgen`（`make_symmetry_cases.py` 还需要 spglib）
